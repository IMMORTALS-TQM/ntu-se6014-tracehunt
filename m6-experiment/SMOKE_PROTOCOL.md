# Deterministic integration protocol

No model or M5 state machine runs here. M6 calls the repository's real M4 ToolSet
through its Python API with either a strict fixture backend or the read-only ES backend.
The fixture backend implements only the query shapes used here, not full Elasticsearch.

Discover the three sources, inspect bounds, search failed logons, network-logon success,
PowerShell (exact process name) and the workstation HTTP connection. Fetch all returned IDs, aggregate
logon event codes, run the Windows failure/success sequence tool, then obtain query history.
Retain exact M4 ledger records, typed tool responses and backend responses. Use fresh IDs
for runs A/B. The smoke verdict is inconclusive because M5 hypothesis verification did not run.
Compare the two tool runs as engineering integration, never as agent repeatability.

V3 binds effective M4 limits. The fixture rejects unsupported phrase analysis. Inspect
the archived command line for the encoded flag, instead of querying the wildcard field
with substring semantics. Any aggregate/sequence truncation marks the run incomplete.
